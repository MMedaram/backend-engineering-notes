# System Design

System design is the practice of turning product requirements into a reliable,
scalable, secure, and maintainable technical solution.

This section starts with requirements before moving into estimation, data design,
APIs, caching, messaging, resilience, and complete high-level design case studies.

## Learning order

1. Functional vs non-functional requirements
2. Assumptions and constraints
3. Capacity estimation
4. Latency, throughput, and concurrency
5. Availability and reliability
6. Scalability
7. Consistency and durability
8. Monolith vs modular monolith vs microservices
9. Load balancers
10. Reverse proxy
11. API Gateway routing with Eureka
12. Backend for Frontend (BFF)
13. Service discovery and Eureka 
14. Core architecture components 
15. Data, caching, and messaging 
16. Reliability, security, and observability 
17. End-to-end system design case studies
